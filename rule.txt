1. 가상환경 설정 및 실행 (New!)
환경 격리: 프로젝트마다 독립된 파이썬 가상환경(.venv)을 생성하고 사용하여 라이브러리 간 충돌을 방지한다.

자동 세팅: 프로젝트 시작 시 가상환경이 없다면 자동으로 생성(python -m venv .venv)하고, 활성화하는 명령어를 제안한다.

패키지 설치: 가상환경 활성화 후 requirements.txt에 명시된 라이브러리를 자동으로 설치(pip install -r requirements.txt)한다.

실행 자동화: 스트림릿 앱을 실행할 때마다 매번 명령어를 물어보지 않고, 터미널에서 즉시 실행할 수 있는 streamlit run app.py 명령어를 실행하거나 제안한다.



2. 개발 환경 및 도구 설정
프레임워크: UI와 웹앱 구현은 Streamlit을 기본으로 사용한다.

데이터베이스: 모든 데이터 저장 및 관리는 구글 스프레드시트(Google Sheets)와 연동한다.

라이브러리 관리: 새로운 패키지를 설치하거나 사용할 때마다 requirements.txt 파일에 자동으로 업데이트한다.

버전 관리: 깃허브(GitHub) 저장소 업로드 시 민감 정보 누출 방지를 위해 .gitignore 설정을 항상 최신으로 유지한다.



3. 코드 작성 및 구조 가이드 (업데이트)

모듈화 원칙: 하나의 파일이 너무 길어지지 않도록(약 100~150라인 내외) 기능을 중심으로 파일을 분리한다.

app.py: 메인 화면 구성 및 Streamlit UI 레이아웃만 담당.

google_sheets.py: 구글 시트 연동, 데이터 읽기/쓰기 로직 전담.

utils.py 또는 logic.py: 복잡한 계산이나 공통 함수 관리.

가독성 우선: 코드를 전혀 모르는 사람도 흐름을 이해할 수 있도록 모든 주요 로직에 상세한 한글 주석을 작성한다.

보안 원칙: 구글 시트 ID나 API 키 등은 secrets.toml 기능을 활용하여 별도로 관리한다.


4. 실행 테스트 및 자가 점검 규칙

작성 후 실행: "모든 코드를 작성하거나 수정한 후에는 반드시 터미널에서 실행하여 문법 오류나 런타임 에러가 없는지 자가 점검한다."

핵심 로직 검증: "특히 '글자 수 제한(100자)'과 '덮어쓰기 로직'이 실제 시트와 연동되어 의도한 대로 작동하는지 시뮬레이션 테스트를 수행한다."



5. 깃허브 동기화 및 기록 규칙

원자적 커밋: "의미 있는 기능 단위(예: 관리자 페이지 완성, 시트 연동 완료 등)로 개발이 끝날 때마다 깃허브에 커밋(Commit) 및 푸시(Push)한다."

커밋 메시지: "커밋 메시지는 한글로 작성하되, 어떤 기능을 추가하거나 수정했는지 명확하게 기록한다."

환경 변수 보호: ".gitignore를 철저히 관리하여 보안 파일(secrets.toml, JSON key 등)이 절대 깃허브에 업로드되지 않도록 강제한다."
