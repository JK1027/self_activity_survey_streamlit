1. 가상환경 설정 및 실행
환경 격리: 프로젝트마다 독립된 파이썬 가상환경(.venv)을 생성하고 사용하여 라이브러리 간 충돌을 방지한다.

자동 세팅: 프로젝트 시작 시 가상환경이 없다면 자동으로 생성(python -m venv .venv)하고 활성화 명령어를 제안한다.

패키지 설치: 가상환경 활성화 후 requirements.txt에 명시된 라이브러리를 자동으로 설치(pip install -r requirements.txt)한다.

실행 자동화: 스트림릿 앱 실행 시 매번 명령어를 묻지 않고, 터미널에서 즉시 실행할 수 있는 streamlit run app.py 명령어를 제안하거나 실행한다.

2. 개발 환경 및 도구 설정
프레임워크: UI와 웹앱 구현은 Streamlit을 기본으로 사용한다.

데이터베이스: 모든 데이터 저장 및 관리는 구글 스프레드시트(Google Sheets)와 연동한다.

라이브러리 관리: 새로운 패키지를 설치하거나 사용할 때마다 requirements.txt 파일에 자동으로 업데이트한다.

버전 관리: 깃허브 저장소 업로드 시 민감 정보 누출 방지를 위해 .gitignore 설정을 항상 최신으로 유지한다.

3. 코드 작성 및 보안 원칙
모듈화 원칙: 파일당 약 100~150라인 내외로 유지하며 기능을 분리한다.

app.py: 메인 UI 및 레이아웃 담당.

google_sheets.py: 데이터 읽기/쓰기 로직 전담.

admin.py: 관리자 페이지 및 주제 설정 로직.

보안(Secrets) 관리: 구글 시트 ID나 API 키 등은 secrets.toml을 활용한다. 로컬 환경과 배포 환경(Streamlit Cloud)에서 즉시 작동할 수 있도록 가이드를 작성한다.

아이패드 최적화: 모든 UI는 아이패드 가로/세로 모드에서 반응형으로 구현한다. 특히 버튼 크기(최소 44px 이상)와 여백은 터치 조작이 원활하도록 충분히 확보한다.

가독성: 주요 로직에 상세한 한글 주석을 작성한다.

4. 실행 테스트 및 자가 점검
작성 후 실행: 모든 코드를 수정하면 반드시 터미널에서 실행하여 문법 오류나 런타임 에러가 없는지 자가 점검한다.

핵심 로직 검증: '글자 수 제한(100자)'과 '덮어쓰기 확인 팝업' 로직이 실제 시트와 연동되어 의도한 대로 작동하는지 시뮬레이션 테스트를 수행한다.

5. 깃허브 동기화 및 기록
원자적 커밋: 의미 있는 기능 단위로 개발이 끝날 때마다 깃허브에 커밋(Commit) 및 푸시(Push)한다.

커밋 메시지: 한글로 작성하되, 수정 사항을 명확히 기록한다.

환경 변수 보호: 보안 파일(secrets.toml, JSON key 등)이 절대 깃허브에 업로드되지 않도록 .gitignore를 강제 적용한다.

6. 자가 검증 및 제한적 수정 루프
최대 10회 자가 수정: 오류 발생 시 스스로 원인을 분석하여 수정하되, 이 과정을 최대 10회까지만 반복한다.

사용자 개입 보고: 10회 이내에 해결되지 않을 경우, 무작정 반복하지 말고 다음 내용을 정리하여 보고한다.

오류 내용: 에러 메시지 핵심 요약.

시도한 방법: 실패한 해결 로직들.

확인 필요 사항: 사용자가 확인해야 할 환경 설정(권한, 경로 등)이나 의사 결정 사항.

7. 테스트 환경 정리 (Clean-up)
브라우저 자동 종료: 셀레니움 등 자동화 테스트 종료 직후 반드시 브라우저 인스턴스를 종료(close/quit)하여 리소스를 해제한다.

헤드리스 모드 우선: UI 확인이 불필요한 로직 테스트는 '헤드리스 모드'를 기본으로 하여 작업 흐름을 방해하지 않는다.

최종 보고: 성공적으로 수정되었을 때만 "자가 검증 완료" 메시지와 함께 결과물을 제출한다.
